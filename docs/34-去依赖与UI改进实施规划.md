## 0. dsh-context 算法调研结论（bowenliang123/dsh-context，Apache-2.0）

已读其源码（GitHub main + 本机 0.85.1 安装包）：

- **token 估算**：`CHARS_PER_TOKEN=4`；文本块 `ceil(len/4)+4`（块开销）；每条消息按角色再 +4；
  非文本块按 JSON 序列化长度折算；图片按 patch 网格模型（14×3 patch，上限 1024）。
- **七类构成**：system（最后一个非零的 system/message）、tools（header 工具 schema 求和）、
  user / inject（developer + 插件注入 + 压缩摘要注入）/ skill（skill 调用与目录）/ assistant / tool（工具结果）
  ——按事件类型与 message.source.kind 分类，逐条估算累加为 `current`。
- **锚定**：有真实 usage 时（`anchoredParts`），把估算的各类构成等比缩放到真实输入总量——
  这是其数字可信的关键。**我们的对比方案依赖同样锚定到真实输入，各类占比的差异只来自估算器细节。**
- 我们自己的 `partsOf` 本来就是它的 `officialParts` 的镜像（当初照着行为写的）——缺的只是 `current` 的数据源。

## 1. 数据源替代设计（去 dsh-context 依赖）

日志里已有全部所需原料：

| 需要 | 来源 | 说明 |
|:--|:--|:--|
| 工具定义 | 最后一个 `request/header` 的 `header.tools[]`（完整 schema） | 每个工具 `ceil(JSON(schema).len/4)+4` 求和 |
| 模型窗口 | 最后一个 `request/context` 的 `contextWindow` | 1048576 等 |
| 输出预留 | 最后一个 `request/header` 的 `header.config.maxTokens` | 压缩点 = 窗口 − maxTokens − 4096 |
| 七类构成 | 会话事件折叠估算（system/user/inject/skill/assistant/tool）+ `request/header` 工具求和 | 按 dsh-context 同款分类规则与估算公式 |
| 真实输入锚 | 最后请求 usage（uncached + cacheRead + cacheWrite） | 锚定缩放，让估算构成贴合真实总量 |

投影（contextTimeline/contextBreakdown/contextPressure）存在时仍优先采用（数字最准）；
**缺失时回退到自有计算**——构成、压缩点、占用率在无 dsh-context 的环境全部可用。
