# Agent Handoff Protocol · v1

当前会话需要交接给一个新的 Session。请按下面的步骤整理、落盘、输出接管消息。
**不要重写任务，也不要顺便继续推进新工作。**

## 0. 先自检

开始前确认一件事：本会话的标题应为「{{SESSION_TITLE}}」。

若不是，请立刻停下来告诉我：
「当前会话标题是 X，不是 {{SESSION_TITLE}}，可能贴错了会话」，然后等我的确认。

## 1. 提取有效状态

- 最终目标、用户要求、关键约束
- 已完成的工作、当前进度、正在处理的问题
- 已确认的决策、采用的方案及其原因
- 尚未解决的问题、风险、下一步

不要机械复述聊天历史。区分「已验证事实」「推测」「未知」；信息冲突时以最新确认的结论为准，
无法确认的明确标注。优先保留最新且仍然有效的内容。

## 2. 盘点成果并确保落盘

检查当前工作区里的实际文件与成果（代码、文档、报告、数据、设计稿等）。

- 重要成果必须已经真实保存在磁盘，不能只存在于对话里
- 保持原有目录结构、文件命名和版本习惯
- 不得为了整理而移动、覆盖或删除原始文件
- 不重复创建已有的成果，不把未验证的内容写成完成品
- 不写 API Key、密码、令牌、Cookie 等凭据；工作区如有 `.env` / credentials，
  只记录文件名，不读取内容

## 3. 写交接文件

在当前任务的工作目录下创建 `HANDOFF-{{HANDOFF_ID}}.md`，
然后**覆盖** `HANDOFF-CURRENT.md`，让它只有一行：指向刚创建的那个文件（含文件名与时间）。

`HANDOFF-{{HANDOFF_ID}}.md` 只包含这七节：

1. 目标与背景
2. 当前有效状态、已完成成果
3. 关键文件：绝对路径 / 用途 / 版本或最后修改时间
4. 已确认的决策与约束
5. **已否决（不要重做）**：方案 / 为什么否决 / 什么条件下可以重新考虑
6. 未完成事项与明确的下一步
7. 风险、依赖、需要用户确认的问题

要求：

- 每条「已完成」都要带可核对的证据（文件路径 / 命令输出 / URL / 时间）；
  拿不出证据的写 `[未验证]`，不要模糊成「已完成」
- 全文不超过 150 行；超了说明没提炼
- 不要复制无关历史；已废弃的方案只保留在第 5 节，不要散落在别处

## 4. 输出接管消息

在回复里输出一段可直接复制给新 Session 的消息，用下面两行包起来（标记行单独成行，不要改写）：

<<<HANDOFF-MSG
（消息正文）
HANDOFF-MSG>>>

正文必须包含：

- 当前任务目标
- 工作区的绝对路径
- `HANDOFF-CURRENT.md` 的绝对路径
- 新 Agent 的阅读顺序（先读哪个、再读哪个）
- 当前进度、下一步、验收要求
- 必须遵守的约束与已知风险

要求：不超过 25 行；不含任何密钥；不要写「假设你可能贴错会话」之类的猜测。

## 5. 如果写不了盘

若因只读、无权限或沙箱限制无法创建文件：不要停下来，也不要假装成功。
把第 3 节的全文直接输出在回复里，开头标注 `[未能落盘]` 并说明原因，然后照常执行第 4 节。

## 6. 最终输出

只输出三部分：

**A. 交接执行结果** — 已保存的文件与路径；已盘点的关键成果；未能完成或无法确认的事项。

**B. 新 Session 接管消息** — 第 4 节那段，带标记。

**C. 需要用户处理的事** — 只列新 Session 无法自行访问、必须由用户提供或确认的内容。

交接成功的标准：新 Session 能找到已有成果、准确理解当前状态、从正确的位置继续工作，
而不是重头开始或重复询问已经解决的问题。
